what a scan of arch-lab cannot see
A gap is something this scan did not look at — not a fault on the host. None of these can be switched on from this pane; each says what would actually fix it.
CVEs inside container image layerscannot be cleared here
not measured — needs an image scanner (trivy) and a vulnerability database; v0.2
what you can do: the real fix is outside this pane: rebuild the image on a schedule, because a base-image CVE is only fixed by a newer base. Scanning inside layers needs an image scanner (trivy), which 0.1.0 deliberately does not ship. Until then the digest check still tells you a newer build exists.
language packages outside the global treescannot be cleared here
partly measured — cve_libraries reads npm's global tree and the pip environment on PATH; per-project lockfiles, other virtualenvs and vendor/ directories are not read
what you can do: name the project in chat and I will query OSV for its packages ('which of my node/python dependencies have known CVEs in ~/projects/x?'). Reading lockfiles automatically is a 0.2 item; today it is one question away.
operating systems without an adaptercannot be cleared here
not measured — adapters exist for: apt, dnf, pacman, zypper; every other OS answers 'unsupported' with its own id. Not implemented: Alpine (the apk adapter is written but has never read a real host), macOS, and Windows (which needs a PowerShell transport, not a package-manager block)
what you can do: nothing to switch on here: that host answers 'unsupported' on purpose, because reporting it as patched would be a guess. Measuring it means adding an adapter — a code change, not a setting. Until then use the distro's own updater, and open an issue with the distro id from cve_coverage.
advisory attribution on non-Ubuntu hostscannot be cleared here
not attributed — only Ubuntu's security-notice feed is wired (read for release resolute), so on these hosts the pending list is measured but the CVE id behind each update is not named: arch-lab, debian-lab, fedora-lab, opensuse-lab
what you can do: the update is still listed with both versions — you can act on it without the CVE id. A per-distro security feed is a 0.2 item; on Ubuntu hosts the notice feed already names the advisory.
